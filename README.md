# Telegram бот с умной долговременной памятью

Учебный проект VPg05 демонстрирует диалогового Telegram-бота, который хранит
сообщения пользователя в Pinecone и не создаёт смысловые дубли. Перед записью
бот сравнивает embedding нового сообщения с ближайшей записью и возвращает в
логах `inserted` или `skipped`.

## Как работает проект

```text
Сообщение Telegram
        ↓
Embedding через ProxyAPI
        ↓
Поиск ближайшей памяти пользователя в Pinecone
        ↓
score >= порога → skipped
score < порога  → inserted
        ↓
Релевантная память + текущее сообщение → текстовая модель
        ↓
Ответ пользователю
```

Для каждого Telegram `user_id` используется отдельный Pinecone namespace.
Открытый идентификатор не включается в название: приложение сохраняет его
SHA-256-отпечаток. В метаданные Pinecone записывается только исходный текст
пользователя, источник и время создания. Ответы бота и служебные промпты в
память не попадают.

## Структура

```text
bot.py                  Telegram-интерфейс
pinecone_manager.py     embeddings, поиск и сохранение памяти
api_client.py           генерация ответа через ProxyAPI
config.py               загрузка и проверка настроек
logging_config.py       безопасное логирование
preflight.py            проверка API без запуска polling
tests/                  офлайн-тесты
```

## Установка

Требуется Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
PINECONE_API_KEY=ключ_Pinecone
PINECONE_INDEX_NAME=tg-dialog-memory
OPENAI_API_KEY=ключ_ProxyAPI
OPENAI_BASE_URL=https://api.proxyapi.ru/v1
EMBEDDING_MODEL=openai/text-embedding-3-small
EMBEDDING_DIMENSION=1536
CHAT_MODEL=openai/gpt-5-mini
MEMORY_DUPLICATE_THRESHOLD=0.74
MEMORY_RETRIEVAL_THRESHOLD=0.30
MEMORY_SEARCH_TOP_K=3
```

Секреты должны находиться только в локальном `.env`. Файл исключён из Git.

## Проверки с внешними сервисами

Проверка embeddings, Pinecone и текстовой модели без запуска Telegram polling:

```powershell
python preflight.py
```

Ручной тест менеджера использует отдельный тестовый namespace, очищает только
его и отправляет четыре фразы:

```powershell
python pinecone_manager.py
```

Ожидаемая последовательность после настройки порога:

```text
action=inserted
action=skipped
action=skipped
action=inserted
```

При итоговой проверке 6 октября 2026 года ручной сценарий менеджера выдал:

```text
action=inserted; similarity_score=none
action=skipped;  similarity_score=0.8003
action=skipped;  similarity_score=0.8452
action=inserted; similarity_score=0.2951
```

Фраза с отрицанием показывает ограничение простого cosine similarity:
тематическая близость не всегда означает одинаковый смысл.

## Запуск Telegram-бота

```powershell
python bot.py
```

На одном токене Telegram должен работать только один polling-процесс.

## Сценарий проверки домашнего задания

1. При необходимости удалить учебный индекс `tg-dialog-memory` в Pinecone.
2. Запустить `python bot.py`. При первом сообщении индекс создастся заново с
   размерностью 1536 и метрикой cosine.
3. Отправить: `Хочу на Марс`.
4. Отправить: `Я полечу на Марс`.
5. Убедиться, что в логах появилась пара `action=inserted` → `action=skipped`.
6. Для проверки новой темы отправить: `Я люблю пиццу` и ожидать `inserted`.

Итоговый чистый Telegram-тест 6 октября 2026 года:

```text
Хочу на Марс       → action=inserted; score=none
Я полечу на Марс   → action=skipped;  score=0.7464
```

Сначала при пороге `0.80` вторая фраза корректно получила фактическое сходство
`0.7464`, но была сохранена как новая. По этому реальному измерению порог
откалиброван до `0.74`. После удаления тестового индекса и чистого повторного
прогона точная пара из задания дала требуемый результат `inserted` → `skipped`.

Порог относится к текущей embedding-модели и набору учебных примеров. После
смены модели или данных его нужно измерить заново, а не переносить вслепую.

## Соответствие домашнему заданию

- Окружение создано: `.venv`, `requirements.txt`, `.env.example` и локальный
  `.env` с ключами. `.env` исключён из Git.
- `pinecone_manager.py` поддерживает `OPENAI_BASE_URL`, создаёт cosine-индекс,
  изолирует пользователей и фильтрует смысловые дубли по порогу.
- В конце `pinecone_manager.py` находится ручной тест на четырёх фразах с
  отдельным namespace.
- `bot.py` обрабатывает отсутствие имени через username или нейтральное
  обращение `пользователь`.
- В Pinecone сохраняются только сообщения пользователя; ответы бота и
  служебные инструкции не сохраняются.
- Тестовый индекс удалён и автоматически создан заново во время чистой
  Telegram-проверки.
- Критерий задания подтверждён логом `action=skipped` для второй фразы.

## Ограничения

- Качество фильтрации зависит от embedding-модели и подобранного порога.
- Cosine similarity не гарантирует распознавание отрицаний и противоречий.
- При смене embedding-модели существующие векторы нужно пересоздать.
- Проект использует внешние сервисы Telegram, ProxyAPI и Pinecone.
- В память нельзя отправлять секретные или реальные чувствительные данные.
